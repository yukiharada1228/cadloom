# NURBS面の定義と接続の保存・復元

`AffineNurbsFaceRecord3` は、版1の `affine-nurbs-face` レコードで、支持NURBSの制御点・正の重み・節点、パラメータ空間の外周・穴のNURBS曲線、senseを保存する。座標と節点・重みは既存の厳密な有理数字列形式を利用する。`AffineNurbsFacesDocument3` はその面レコードの配列であり、材料Bodyのレコードではない。

## 入出力

- `encodeAffineNurbsFace3` は所有された面のみを受け取り、定義幾何の不変なレコードを返す。
- `readAffineNurbsFaceRecord3` と `readAffineNurbsFacesDocument3` は構造をsnapshotする。未知のキー、版、NURBS以外のタグ、不正な数値表記、項目数・数値文字数の超過を拒否する。構造の受理は幾何の認定ではない。
- `decodeAffineNurbsFace3` は支持曲面からアフィン左逆写像とC0継ぎ目を再検査し、Jordan外周・穴・向き、有効矩形内の全境界、lift片と内部点を再構築してから面を所有する。
- `affineNurbsFacesDocument3` / `serializeAffineNurbsFaces3` は所有された面の配列から文書／JSONを作る。
- `parseAffineNurbsFacesDocument3` はJSONの文字数と累積構造予算を検査する。
- `restoreAffineNurbsFaces3` は文書またはJSONから各面を再認定し、全端点での境界分割、全区間の恒等式照合、共通BRep接続を再計算する。

所有権、左逆写像係数、sample、共有辺ID、分割根、接続フラグを保存して信用する方式ではない。特に曲面節点から生じる無理数の切断位置は元の有理幾何から再計算する。読み込み制限は文書全体で累積する。個々の幾何コンストラクターによる重み・節点・単純境界などの検査も省略しない。

定義幾何の整合した変更が有効な別の面を表す場合は、新しい面として受理する。この形式は元ファイルとの同一性を認証する署名ではない。無効な定義や余分な認定フラグで検査を飛ばすことはできない。

## 保証の範囲

復元結果は所有された埋め込み面と接続診断であり、一般のNURBS面、殻全体の幾何的埋め込み・包含・材料、共通Bodyへの採用を認定しない。従来のBody文書のスキーマは変更しない。内部交差の発見と非線形再パラメータ化による共有は引き続き未対応。

## 検証

穴のある面の完全な定義往復、不変snapshot、無理数の位置で分割された境界の共有接続の再生成、6面の立方体の閉接続、負の重み・潰れた支持面・不正な境界・向き・偽認定フラグの拒否、構造受理と幾何受理の分離、版・own fields・有効な別種幾何タグ・累積予算、整合した別の幾何定義の再認定を試験する。全体回帰やTypeScript全体の形式証明の完了を意味しない。
