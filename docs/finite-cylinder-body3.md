# Owned finite-cylinder Boolean Bodies

`bodyFromFiniteCylinderBoolean3` adopts an owned manifold two-cylinder Boolean into the existing `Body3` contract. `booleanCylinderBodies3` obtains finite cylinders from existing owned cylinder Bodies, executes the exact lower-level Boolean and adopts its result. Additional clipping planes remain rejected. Previous curved Boolean and expression results are now accepted through the [expression backend](cylinder-expression-body3.md). Duplicate axial cap constraints do not change the primitive; additional retained constraints are not silently dropped.

Adoption derives shell/cavity roles and strict material samples with `finiteCylinderBooleanRegions3`, restores and binds every mixed bounded face, and requires closed manifold incidence, no topology issues, one strict sample per bounded material region and agreement with the constructive material locator. Common `locateBody3`, `locateBodyFace3`, document and serialization APIs preserve private factory ownership. Empty and disconnected material and reversed cavity shells use the same contract.

`Body3.topology` now admits native curves or the mixed native/SSI edge backend, and face domains similarly admit mixed boundaries. Existing native Bodies retain their native runtime representation. Native-only planar conversion/consolidation checks the private native backend before accessing topology rather than casting mixed edges. Cylinder clipping/splitting likewise requires its actual constructive cylinder backend. This broadens TypeScript types: callers inspecting common topology must distinguish curve kinds.

A new `finite-cylinder-boolean` construction record contains two normalized finite-cylinder definitions and the operation. It is generated from the owned source. Restoring a document replays its construction, re-derives material regions and compares every stored ordered field semantically at exact scalar/point values. The exact-point equivalence check includes rational-function and biparametric charts, so equivalent point representations are accepted while altered values fail. A recipe label alone never certifies an unrelated boundary or void table.

This completes common owned Body adoption and replay persistence for the restricted constructive family. It does not import arbitrary curved BReps, certify arbitrary analytic/NURBS shells, support nonmanifold material as Body3, or allow the resulting curved Body as a subsequent Boolean operand. The existing lower-level APIs retain nonmanifold results rather than discarding them.

Tests cover common material/face queries and JSON replay, cavity/disconnected/empty regions, ownership and nonmanifold rejection, altered recipes/region roles/witnesses, explicit backend restrictions, and equivalent versus altered rational-map point records. These executable checks and existing selected Lean audits do not constitute full TypeScript formal verification.
