# 有理数線分の交差と分割の正当性証明

## 証明の対象と強さ

対象は `Rational`、`pointOnSegment`、`intersectSegments`、`splitSegments` が実装する数学的アルゴリズムである。有限の有理数座標の閉線分列について、交差の完全性、分割の完全性、入力元情報、正規化、幾何学的な非交差性を示す。

対応する実装の基準コミットは `0ad490fd207aeeb0d82884aaba87f33fabb20720`。対象関数を変更した場合には、以下の実装対応と証明の前提を再レビューする必要がある。

これは形式仕様と不変条件に基づく手書きの演繹証明である。テスト結果を証明の代用にしない。Lean、Coq等が受理した証明項ではなく、TypeScriptやECMAScriptの形式意味論から実行コードを機械検証したものでもない。

この文書とは別に、[Lean検証プロジェクト](../../formal/README.md)で一部の補題と実装から抽出した式を機械検証している。そこには非平行交差と区間分割の補題が含まれるが、この文書の全定理、およびTypeScript実装全体が機械検証済みという意味ではない。対象ごとの状態は`formal/verification-status.json`に記録する。

### 前提

1. 入力は有限かつ密な線分配列である。各座標は本実装の通常の `Rational` コンストラクターで作った値であり、偽造オブジェクト、振る舞いを変えるサブクラス、Proxy、改変した組み込み関数を含まない。
2. 分子は整数、分母は正の整数で、両者は互いに素である。
3. BigIntの整数演算と比較、文字列化、Map、配列の走査・整列・添字付けが仕様通り動作する。配列長・頂点番号は安全に表現可能な整数の範囲内にある。
4. 計算を完了する時間・メモリがあり、外部から実行を中断されない。

前提3は信頼する実行基盤であって、この文書が証明する対象ではない。メモリ不足時の成功、異常なJavaScriptオブジェクトの受理、近似データの実世界での真値、曲線、曲面、CADファイル互換性は結論に含めない。

## 1 数学的な仕様

座標は $\mathbb Q^2$ の元とする。線分は実平面上の集合

$$[a,b]=\{a+t(b-a)\mid t\in\mathbb R,\ 0\le t\le1\}$$

である。したがって $a=b$ のときは一点集合である。入力を $S_0,\ldots,S_{n-1}$ とする。

辞書順 $p<q$ は、$p_x<q_x$、または $p_x=q_x$ かつ $p_y<q_y$ と定義する。非退化線分 $S$ の内部 $\operatorname{int}_S(S)$ は、パラメーター $0<t<1$ の点であり、平面内の位相的内部とは異なる。

入力端点集合を $E$ とする。各ペアの分割点集合 $B_{ij}$ を次のように定義する。

- $S_i\cap S_j=\varnothing$：$B_{ij}=\varnothing$。
- 共通部分が一点 $p$：$B_{ij}=\{p\}$。
- 共通部分が非退化線分 $[p,q]$：$B_{ij}=\{p,q\}$。

全頂点候補と、各入力の分割点を

$$V=E\cup\bigcup_{i<j}B_{ij},\qquad
C_i=\{a_i,b_i\}\cup\bigcup_{j\ne i}B_{ij}$$

とする。$B_{ji}=B_{ij}$ と約束する。

出力は以下を満たすことを仕様とする。

1. 頂点は $V$ とちょうど一致し、座標順に重複なく並ぶ。
2. 各 $C_i$ の辞書順で隣り合う相異なる点を結んだ線分を生成し、同じ幾何学的な辺は一つにまとめる。
3. 頂点 $v$ の `sources` は $\{i\mid v\in S_i\}$ と一致する。
4. 辺 $e$ の `sources` は $\{i\mid e\subseteq S_i\}$ と一致する。
5. 各非退化入力は、その入力元番号を持つ出力辺の和集合と一致する。退化入力は頂点として残る。
6. 異なる出力辺の共通部分は空か、双方の端点である一点である。出力頂点はどの辺の相対内部にも存在しない。

## 2 有理数表現の正当性

### 補題 2.1 正規化

整数 $n$、非零整数 $d$ に対し、$g=\gcd(|n|,|d|)>0$、$s=\operatorname{sign}(d)$ とする。コンストラクターの出力は $(ns/g,ds/g)$ である。比は $n/d$ のまま、分母は正、分子・分母は互いに素である。$n=0$ なら $g=|d|$ より必ず $(0,1)$ になる。

`gcd` のループは $\gcd(a,b)=\gcd(b,a\bmod b)$ を不変条件に持つ。非負の $b$ は、零でない各反復で真に減少するため停止し、終了時の $a$ は最大公約数である。よって正規化は正しい。□

### 補題 2.2 演算とキー

四則演算は通常の分数の公式に従い、生成のたびに補題2.1で正規化される。除数の分子が零の場合は除算前に拒否する。正の分母同士なので、比較は $n_1d_2-n_2d_1$ の符号と等しい。

正規化された有理数表現は一意である。既約な $a/b=c/d$、$b,d>0$ に対し $ad=bc$ であり、互いに素であることから $b\mid d$、$d\mid b$、よって $b=d$、$a=c$ となる。

従って `toString()` は有理数ごとに一意である。整数と分数の文字列表現にはカンマを含まないので `x + ',' + y` は座標ペアに対して単射である。`pointKey` による統合は等しい点だけを統合する。□

### 補題 2.3 小数文字列

許可された小数文字列の符号を $s$、整数部の絶対値を $w$、小数部分を桁数 $k$ の非負整数 $f$ とすると、文字列から構成される分数は $s(w10^k+f)/10^k$ である。`-0.125` のように整数部が負の零の場合も、符号を含む文字列を連結してBigIntに変換するため、この式になる。整数・分数文字列も対応する整数比そのものである。浮動小数点への変換はない。□

## 3 点の所属と二線分交差

### 補題 3.1 線分上の辞書順

相異なる $a,b$ を $a<b$ となるように並べる。$u=b-a$ は $u_x>0$、または $u_x=0,u_y>0$ を満たす。したがって $a+tu$ は実数パラメーター $t$ に関して辞書順で狭義単調増加する。

よって直線上の点 $p$ について $p\in[a,b]$ と $a\le p\le b$ は同値である。□

### 補題 3.2 `pointOnSegment`

非退化線分の場合、`orient2d` は $(b-a)\times(p-a)$ の符号を厳密に求める。その値が零であることは同一直線上にあることと同値であり、補題3.1の範囲検査と合わせて所属を正しく判定する。

退化線分 $a=b$ では向きの値は常に零だが、$a\le p\le a$ は $p=a$ を意味する。よって退化時も正しい。□

### 定理 3.3 `intersectSegments` の健全性と完全性

入力を $[a,b]$ と $[c,d]$ とする。

**退化する場合。** 一方が一点なら、共通部分はその点が他方に所属するときだけその一点である。補題3.2によって実装の分岐は正しい。両方が一点でも同じ議論が成立する。

以下は双方が非退化の場合である。$r=b-a$、$s=d-c$、$w=c-a$、$D=r\times s$ と置く。

**$D\ne0$ の場合。** 直線の交点条件は $tr-us=w$ である。両辺と $s$ の外積、および両辺と $r$ の外積を取ると、唯一の候補は

$$t=\frac{w\times s}{D},\qquad u=\frac{w\times r}{D}$$

となる。逆にこの $t,u$ は $tr-us=w$ を満たす。例えば $z=tr-us-w$ は $r,s$ 双方との外積が零であり、$r,s$ が独立なので $z=0$ である。従って両閉線分に共通点があることと $0\le t\le1$ かつ $0\le u\le1$ は同値で、その場合の共通部分は $a+tr$ のみである。

補題2.2により、実装の符号検査と `numerator > denominator` はこの範囲検査を厳密に行う。$D$ は非零であり、この分岐でゼロ除算はない。交点は有理数演算だけで構成される。

**$D=0$ の場合。** 非零ベクトル $r,s$ は平行である。$(b-a)\times(c-a)\ne0$ なら直線が異なるため共通部分はない。零なら同一直線であり、補題3.1により共通部分は閉区間の共通部分として計算できる。各線分の小さい端点の最大を $l$、大きい端点の最小を $h$ とすると、$l>h$ なら空、$l=h$ なら一点、$l<h$ なら $[l,h]$ である。これが実装の三分岐そのものである。

以上ですべての場合を尽くし、返す共通部分は実際の共通部分と一致する。□

## 4 分割点の完全性

### 補題 4.1 全体の頂点は各通過線分にも記録される

すべての $i$ に対して $C_i=V\cap S_i$ である。

**$C_i\subseteq V\cap S_i$。** 自分の端点と、自分を含むペアの共通部分の端点のみを追加するので明らかである。

**$V\cap S_i\subseteq C_i$。** $v\in V\cap S_i$ とする。

まず $v$ が入力線分 $S_j$ の端点の場合を考える。$j=i$ なら初期化時に入る。$j\ne i$ のとき、$S_i\cap S_j$ は $v$ を含む。一点なら $v\in B_{ij}$。非退化区間なら、$S_j$ の端点 $v$ はその共通区間の端点でもあるため、やはり $v\in B_{ij}$ である。従って $v\in C_i$。

次に $v$ が入力端点でない場合を考える。定義より、あるペアの $B_{jk}$ に含まれる。非退化な共通区間の端点は入力端点なので、この場合はあり得ない。同一直線の二区間が一点で接する場合もその点は入力端点である。退化線分の共通点も入力端点である。

従って $v$ は、非平行な非退化線分 $S_j,S_k$ の一意な交点である。$S_i$ が退化していれば $v$ は自分の端点になり、すでに処理済みである。そうでなければ $S_i$ の支持直線は、非平行な二直線の少なくとも一方とは非平行である。その線分を $S_j$ とすれば $S_i\cap S_j=\{v\}$ となるので、$v\in B_{ij}\subseteq C_i$。$i=j$ または $i=k$ なら元のペアで記録される。

いずれの場合も $v\in C_i$。両包含より結論を得る。□

### 補題 4.2 ペアループの不変条件

処理済みの順不同ペア集合を $P$ とする。各入力のMapが持つ座標集合は、常に

$$\{a_i,b_i\}\cup\bigcup_{\{i,j\}\in P}B_{ij}$$

に等しい。

初期化では $P=\varnothing$ なので成立する。各反復で定理3.3が正しい $B_{ij}$ を求め、双方のMapへ追加する。他の要素は変更せず、補題2.2でキーの衝突もないため不変条件は維持される。二重ループは全順不同ペアを一度ずつ処理する。終了時のMapは正確に $C_i$ となる。□

## 5 出力の正当性

### 定理 5.1 頂点と頂点の入力元

`vertexMap` は各 $C_i$ の各点を一度ずつ訪問するので、頂点集合は $\bigcup_i C_i=V$ である。ある頂点に $i$ を追加することと $v\in C_i$ は同値であり、補題4.1からこれは $v\in S_i$ と同値である。

外側の `forEach` は入力番号の昇順、各Map内の点は一意なので、`sources` は重複なしの昇順になる。辞書順は全順序であり、相異なる点の比較が零になることはないため、頂点の整列も一意である。□

### 定理 5.2 入力形状の保存

非退化 $S_i$ に対して、その端点を含む有限集合 $C_i$ を $p_0<\cdots<p_m$ と並べる。$p_0,p_m$ は $S_i$ の端点である。補題3.1により、

$$S_i=\bigcup_{k=0}^{m-1}[p_k,p_{k+1}]$$

であり、隣接区間以外に内部の重なりはない。実装はちょうどこの隣接ペアを生成する。辺を統合しても幾何学的な和集合は変わらず、入力元番号も残る。退化入力では $C_i$ は一点であり、辺生成ループは零回、頂点は定理5.1により保存される。□

### 定理 5.3 辺の内部に頂点は残らない

生成辺 $e=[p_k,p_{k+1}]\subseteq S_i$ の内部に $v\in V$ があると仮定する。補題4.1から $v\in C_i$ であり、補題3.1から $p_k<v<p_{k+1}$ となる。これは隣接した点を選んだことに矛盾する。従ってそのような頂点はない。□

### 定理 5.4 辺の入力元は完全かつ正確

辺 $e$ が $S_i$ から生成されたなら、凸性から $e\subseteq S_i$ なので入力元の記録は健全である。

逆に、出力辺 $e=[p,q]$ が $S_j$ に含まれるとする。$p,q\in V\cap S_j=C_j$ である。間に別の $C_j$ の点があれば定理5.3に反する。従って $p,q$ は $C_j$ でも隣接し、$S_j$ の処理で同じ辺が生成されて番号 $j$ が追加される。これで完全性も得られる。

辺キーは異なる頂点番号の組であり、始点番号が常に終点番号より小さいため、同じ幾何学的辺は同じキーになる。番号は入力順に一度ずつ追加され、`sources` は重複なしの昇順である。□

### 定理 5.5 異なる出力辺は共通端点以外で交差しない

出力辺 $e\subseteq S_i$、$f\subseteq S_j$ を取る。

支持直線が非平行なら、共通点 $x$ がある場合 $S_i\cap S_j=\{x\}$ である。よって $x\in B_{ij}\subseteq V$。定理5.3から $x$ は双方の端点でなければならない。平行かつ異なる直線なら共通点はない。

同一直線上では、二つの閉区間が正の長さで重なり、しかも異なる区間なら、少なくとも一方の端点が他方の相対内部に存在する。全端点は $V$ に属するので定理5.3に矛盾する。完全に一致する辺は同じキーで既に統合されている。一点だけで接する場合、その点は双方の端点である。

従って異なる出力辺の共通部分は空、または共通端点一点に限られる。□

## 6 決定性と再分割

### 定理 6.1 順序と向きへの不変性

入力の端点を反転しても $S_i$ は集合として変わらない。入力の置換も線分集合と $V$ を変えない。補題4.1から各線分上の分割位置も変わらず、頂点は座標順、辺は頂点番号順に一意に並ぶので、出力の座標と辺番号は変わらない。

置換後の入力を $S'_j=S_{\pi(j)}$ とすると、`sources` は各集合 $A$ に対して $\{j\mid\pi(j)\in A\}$ に置き換わる。番号そのものが不変なのではなく、対応する入力を正しく追跡するという保証である。□

### 定理 6.2 幾何学的な冪等性

出力辺を再入力し、すべての出力頂点を零長線分として追加する。全頂点は再入力端点に含まれ、定理5.3と5.5から、新しい交点や分割位置は生じない。従って再分割後の頂点・辺は元のものと一致する。`sources` は新しい入力に対する番号になる。

零長線分を追加しなければ孤立頂点が失われ得るので、その場合に頂点まで同一になるとは主張しない。□

## 7 停止性と実装への対応

有限入力に対してペア数は $n(n-1)/2$ 個である。各反復が追加する点は高々二つ。各Mapと整列対象は有限であり、有理数演算も有限整数上の演算と停止する最大公約数計算からなる。資源に関する前提の下でアルゴリズムは停止する。

| 実装箇所 | 数学上の対応と根拠 |
|---|---|
| `numeric/rational.ts` のコンストラクター・演算 | 補題2.1〜2.3 |
| `geometry/orient2d.ts` と `pointOnSegment` | 補題3.1〜3.2 |
| `intersectSegments` の退化・平行・非平行分岐 | 定理3.3の三場合 |
| `splitSegments` の `cuts` とペアループ | 補題4.2の不変条件 |
| `vertexMap` と `vertexIndices` | 補題2.2、定理5.1 |
| `ordered` の隣接ペア生成 | 定理5.2〜5.3 |
| `edgeMap` の統合と入力元追加 | 定理5.4 |
| 出力のソート | 定理6.1 |

以上から、前提の下で数学的アルゴリズムは仕様1〜6を満たす。実装の各処理も上表の通り対応している。ただし、この対応表自体は人手のレビューであり、実行コードの機械検証ではない。
