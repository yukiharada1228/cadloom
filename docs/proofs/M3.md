# M3 の証明対応表

M3で`formal/CadloomFormal/`に追加したLeanの定理（`Primitive.lean`、`Profile.lean`、`Prism.lean`、`Sweep.lean`）と、TypeScriptの実装・テストの対応表です。M0〜M2と同じく`node formal/scripts/verify.mjs`（`npm run prove`）で確かめます。このスクリプトは`lake build`を実行し、全定理の公理を監査して、`propext`・`Classical.choice`・`Quot.sound`の3つ以外に依存しないことを確かめます。Mathlibは使っていません。統合時点では16モジュール・401定理（M3で131定理を追加）が通っています。

## 読み方（共通の前提）

- 前提は[M0.md](M0.md)・[M1.md](M1.md)・[M2.md](M2.md)と同じです。Leanのモデルは**厳密な数学**（`Nat`・`Bool`・`Int`・`Rat`・`List`）で、TSの関数と同じ式・同じ添字・同じデータ構造で書いてあります。TSは倍精度浮動小数点で計算します。**丸め誤差の上界は証明していません。**
- M3の定理は大きく2種類です。(1) **組合せ**: TSのビルダーが割り当てる頂点・辺・面・ループのidとコエッジの順序をそのままモデルにし、Euler–Poincaréの関係、ループが閉じること、各辺が逆向きの2つのコエッジを持つこと（`Paired`）を示します。(2) **有理数の代数**: 面積・体積の公式（Greenの定理、発散定理、Pappus–Guldin）と反射の性質です。
- 実数・`π`・三角関数はcore Leanにありません。円弧は`(c, s)`と仮定`c² + s² = 1`で、回転角`θ`や`Θ`（全周なら`2π`）は記号的な有理数で表します。`π`は共通の係数として外に出します。
- 幾何（曲線・曲面の評価、pcurve、`validateBrepGeometry`、許容誤差）、`Result`のエラー経路、凍結、計算量の上限はLeanの対象外で、テストで確かめます。
- 「テスト」列の名前は`tests/*.test.ts`の`test(...)`名です。定理名と同じ名前（または定理名を含む名前）のテストが、実装に対して同じ性質を確かめます。各テストはTSのビルダーが作ったB-repから`Use`のリストを取り出し、Leanのモデルと**同じリスト**であることを比べます。
- 「補題」は他の定理の証明のための補助的な定理で、対応するTSの関数はありません。
- 仮定は満たすことができます（空虚な定理ではありません）。例: `cylinder_top_cap`（円柱の上の円板が`PoleCap`を満たす）、`Prism.examples_*`・`Sweep.*_examples_*`（具体的な大きさのリストで判定）、`reflect_swap`・`dr_*`の仮定は`r0 = (1, 0, 0)`、`t0 = t1 = (0, 0, 1)`で満たされます（レビュー時に確認）。

## Primitive.lean — `src/primitive/`（`cylinder.ts`、`cone.ts`、`ruled.ts`、`sphere.ts`、`torus.ts`）

## 統合時の変更（M3）

- **公開API**: `src/index.ts`から`profile`・`prism`・`sweep`を公開しました（`primitive`は既に公開済み）。`export *`の名前の衝突はありません（tscと、全モジュールの名前を数える確認、テスト`the package entry exports every M3 area without name collisions`）。根に出すには一般的すぎる名前を改名しました: `MAX_DEPTH` → `PROFILE_CONTACT_MAX_DEPTH`（`src/profile/intersect.ts`）、`reflect` → `reflect3`（`src/sweep/frames.ts`、`dot3`などと同じ接尾辞。Leanの名前は`reflect`のまま）。`placedFrame`・`checkLength`などの内部の補助関数は根に出していません（同じテストで確認）。
- **1つの仕事は1か所で（POLICY §3.5）**
  - **円柱のビルダーは1つ**: 例`examples/box-and-cylinder-mesh.ts`の手組みの`closedCylinder`を削除し、`makeCylinder`を使うようにしました。`makeCylinder`のidはM2の`cylinderLoops`と同じです（`Primitive.cylinder_model_eq`）。`tests/prism.test.ts`の比較（`the extruded circle matches makeCylinder, …`）と`tests/convert.test.ts`の円柱も`makeCylinder`に替えました。`tests/topology-geometry.test.ts`・`tests/tess.test.ts`の円柱は、検証の失敗を作るための変種（pcurveなし、裏返し、壊した継ぎ目など）を組み立てるテスト用の試験体なので残しています。
  - **プリズムの配置は1つ**: `extrude`の`buildRegion`とスイープの`buildRegion`が同じidの割り当て・円板のループ・側面のループをほぼ行ごとに複製していました。これを`buildPrismRegion`（新しい`src/prism/layout.ts`）の1か所にまとめ、呼び出し側はレール（`b_g → t_g`）と側面の曲面・pcurveだけを渡します。`Prism.lean`の対応するTS関数も`buildPrismRegion`です。
  - **線分の平面への配置は1つ**: `src/sweep/section.ts`の`placeSegment`・`segmentNurbs3`・`arcSpan`・`onPlane`・`EdgeGeom`は`src/prism/extrude.ts`の非公開の同名関数の複製でした。`src/prism/layout.ts`へ移し、`extrude`・`revolve`・`sweep`が共有します。ノットを`[0, 1]`に写す`unitKnots`も`extrude`と`sweep`の2か所から1か所にしました。
  - **直線のpcurveは1つ**: `uvSegment`（`(u0, v0) → (u1, v1)`の1次のpcurve）を`src/primitive/placement.ts`から`src/topology/geometry.ts`（`planePcurve`の隣）へ移し、`extrude`の同じ式の`uvLine`を削除しました。
  - **極の表現は1つ**: 球・円錐の頂点・軸に触れる回転は、どれも「辺を持たない頂点と、潰れる等パラメーター線に沿う`(u, v)`の跳び」で表し、`validateBrepGeometry`と表示メッシュは`uvGapCollapses`の1か所で判定します。退化辺を使わない理由は`Primitive.degenerate_pole_edge_shift`です。
  - **スイープは委譲する**: 直線のパスは`extrude`、軸がプロファイル平面にある円弧のパスは`revolve`に委譲します（`sweep along a line equals extrude …`、`sweep along a circular arc whose axis lies in the profile plane is the revolution about it`）。
- **レイヤーの規則**: `src/profile`（カーネルの幾何）が表示メッシュの`src/tess/triangulate.ts`から`segmentsMeet`・`loopOrientation`を読み込んでいました。厳密な2Dの多角形の述語なので、`src/exact/polygon.ts`へ移し、tessとprofileの両方がそこから使います（公開も`exact`から）。`prism`・`sweep`は`primitive`に依存しなくなりました。統合後の依存は`profile → exact/curve/nurbs/surface`、`prism → profile/topology/…`、`sweep → prism/profile/topology/…`、`primitive → topology/surface/curve/…`です。
- **例**: `examples/primitives-and-sweeps.ts`を追加し、`npm run example`で両方の例を実行します。全てのプリミティブ、穴のある板の押し出し、穴のあるプロファイルの3/4回転、らせんに沿う回転最小化スイープを作り、recordのテキストで往復させ、弦の許容誤差0.001でメッシュにして、`artifacts/m3/`にOBJ・record・メッシュと`summary.json`（メッシュの体積、閉じた式による解析的な体積、相対誤差）を書きます。テスト`example (M3): …`は全ての物体が往復で同じテキストになり、水密で向きがそろい、体積の相対誤差が0.5%以内であることを確かめます。

## 既知の限界（M3全体）

- Leanの定理は組合せと有理数の厳密計算についてのものです。曲線・曲面・pcurveの幾何、浮動小数点の誤差、メッシュの幾何的な正しさは証明していません。`Paired`は押し出しと回転では具体例でだけ判定しています（全ての大きさのリストでは証明していません）。
- **primitive**: 部分的なプリミティブ（扇形）、裏返しや負の半径の球、極のない球、楕円錐はありません。半径が`0`より大きく`zoneTol3d`以下の円錐の端は頂点として扱います（upstreamと同じ）。傾きが約`1e8`以上の平たすぎる円錐は`invalid-input`です。円錐の頂点の表示用法線は軸方向の平均1つです。プリミティブの厳密な質量特性は`mass`にありません（メッシュの体積と比べるテストだけです）。
- **profile**: NURBSの接触はBézierの分割（深さ`PROFILE_CONTACT_MAX_DEPTH = 30`、作業量の上限で「接触」と答える側に倒す）で調べるため、つなぎ目でほぼ接するNURBSを拒むことがあります。円弧の交差の位置は浮動小数点で計算します。有理・高次のNURBSの面積はGauss–Legendreの近似です。線分は最大`MAX_PROFILE_SEGMENTS = 2000`です。
- **prism**: 斜めの押し出しでは円弧の側面は楕円柱ではなくNURBS曲面になります。ノットを`[0, 1]`に写すとき、極端に近い2つのノット（相対差`1e-16`程度）が重なることがあり、そのときは`validateBrepGeometry`が拒みます。
- **sweep**: スキンのスイープの誤差は奇数番目のステーションでだけ測り、その間と二重反射の標構の誤差は上界を持ちません（4096個のステーションの標構との比較で最大`4 × approxTol3d`）。曲がり具合の検査はステーションでだけ行い、自己交差は検査しません。回転の検査には保守的なものがあります（軸上にあるNURBSの線分、制御多角形が軸を横切るNURBS）。大域補間`interpolation`は`src/sweep/interpolate.ts`にありますが、本来はNURBSのフィット（M1から後送り）として`src/nurbs`に置くものです。
- **tess**: 有理NURBS曲面の評価（M1の`homogeneousNet`）は評価のたびに重み付きの制御網を作り直すため、細かいらせんに沿う円のスイープのメッシュ化は遅くなります（テストは粗いkernelを使います）。平面のNURBS面では標本の曲率が丸め誤差になり、格子が上限に達することがあります。トーラスの管の半径より大きな弦の許容誤差では、メッシュは水密でも自己交差します。上下の円の半径が違う円錐台の側面は、両方の円を独立に標本化するので斜めの三角形がたわみ、細分で三角形が多くなります（例の円錐台で約6700個、同じ大きさの円柱で約140個）。
