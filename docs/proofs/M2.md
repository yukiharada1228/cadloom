# M2 の証明対応表

M2で`formal/CadloomFormal/`に追加したLeanの定理（`TopologyGeometry.lean`、`Record.lean`、`Tess.lean`）と、TypeScriptの実装・テストの対応表です。M0・M1と同じく`node formal/scripts/verify.mjs`（`npm run prove`）で確かめます。このスクリプトは`lake build`を実行し、全定理の公理を監査して、`propext`・`Classical.choice`・`Quot.sound`の3つ以外に依存しないことを確かめます。Mathlibは使っていません。統合時点では12モジュール・270定理が通っています。

## 読み方（共通の前提）

- 前提は[M0.md](M0.md)・[M1.md](M1.md)と同じです。Leanのモデルは**厳密な数学**（`Nat`・`Bool`・`Int`・`Rat`・`List`・`Option`）で、TSの関数と同じ式・同じ添字・同じデータ構造で書いてあります。TSは倍精度浮動小数点で計算します。**丸め誤差の上界は証明していません。**
- M2の定理の多くは**組合せ的**な主張です。数値ではなく、添字の範囲、語列への符号化、辺の使用回数、耳の切り取りの手順を扱います。幾何（曲線・曲面の評価、pcurveの持ち上げ、許容誤差）はLeanの対象外で、テストで確かめます。
- 配列の範囲外アクセス、`Result`のエラー経路、JSONの形の検査、凍結（`Object.freeze`）、計算量の上限（`MAX_SEGMENTS`など）はLeanの対象外です。
- 「テスト」列の名前は`tests/*.test.ts`の`test(...)`名です。定理名と同じ名前（または定理名を含む名前）のテストが、実装に対して同じ性質を確かめます。
- 「補題」は、他の定理の証明のための補助的な定理で、対応するTSの関数はありません。
- 仮定は満たすことができます（空虚な定理ではありません）。例: `disc_valid`（具体的なrecordが検査を通る）、`cylinder_paired`（具体的な円柱が対をなす）、4頂点の正方形を2通りの耳の選び方で切ると、どちらも面積2の三角形2つになる（レビュー時に確認）。

## 既知の限界（M2全体）

- Leanの定理は組合せと有理数の厳密計算についてのものです。幾何の検査、浮動小数点の誤差の上界、メッシュの幾何的な正しさ（重なりのなさ、たわみの最大値）は証明していません。
- **topology**: `validateBrep`・`validateBrepGeometry`は、`Brep`の型を満たさない入力（曲線のない辺など）で`TypeError`を投げます。信頼できない入力はrecordとconvertを通してください。ループの`(u, v)`での連続性・巻き数・自己交差は検査しません。pcurveの偏差は内部の8点で確かめるだけで、パラメーターの1対1の対応は確かめません。継ぎ目の2本のpcurveの距離は`(u, v)`で測りますが、許容誤差は3Dの`zoneTol3d`です。`planePcurve`はNURBSの辺を部分区間に切れません。
- **record / convert**: recordはビルダー順（コエッジはループごとに巡回順、子のリストは昇順）でだけ受け付けます。保存された座標系は、kernelが作る座標系と各成分`1e-12`以内のときだけ保ちます。`-0`は`0`として読みます。曲線・曲面・pcurveの重複は除きません。upstreamの許容誤差・領域・ワイヤー・折れ線・交線・回転面・ブレンド面の種類はまだありません。
- **tess**: 表示用のメッシュです。面のたわみは三角形の重心で確かめるだけで、上限（`MAX_GRID`、`MAX_SEGMENTS`、`MAX_LINE_SEGMENTS`、sagの上限）に達すると統計に報告し、弦の許容誤差を超えることがあります。耳切りは面ごとに最悪`O(n²)`です（各辺1024点の正方形で約2秒）。球の極・円錐の頂点の処理には、まだ球・円錐の極を含む試験体がありません。NURBS面の境界の`(u, v)`は同じ割合のpcurveの値です。穴が他のループに頂点で接する面は失敗として報告します。
- 例の円柱は`BrepBuilder`で組み立てています。解析的なプリミティブ（円柱・球・円錐・トーラス）はM3です（M3で例の円柱を`makeCylinder`に置き換えました。[M3.md](M3.md)）。
