# M0 の証明対応表

M0で`formal/CadloomFormal/`に置いたLeanの定理と、TypeScriptの実装・テストの対応表です。証明の範囲は`node formal/scripts/verify.mjs`（`npm run prove`）で確かめます。このスクリプトは`lake build`を実行し、全定理の公理を監査して、`propext`・`Classical.choice`・`Quot.sound`の3つ以外に依存しないことを確かめます。Mathlibは使っていません。

## 読み方（共通の前提）

- Leanのモデルは**有理数（`Rat`）上の厳密な数学**です。TSの関数と同じ式・同じ添字・同じ再帰構造で書いてあります。ただし、TSは`exact`の厳密経路を除いて倍精度浮動小数点で計算します。**丸め誤差の上界は、特記がない限り証明していません。** テストでは許容誤差つきで同じ性質を確かめています。
- 配列の範囲外アクセス、`Result`のエラー経路、入力検証（有限性・オーバーフロー判定）、凍結（`Object.freeze`）はLeanの対象外です。これらはテストで確かめます。
- 「テスト」列の名前は`tests/*.test.ts`の`test(...)`名です。定理名と同じ名前のテストが、実装に対して同じ性質を確かめます。
- 「補題」は、他の定理の証明のための補助的な定理で、対応するTSの関数はありません。

## 既知の限界（M0全体）

- 全ての定理は有理数の厳密計算についてのものです。浮動小数点の丸めの上界は証明していません（例外は`exact`の厳密経路で、ここは二進有理数で厳密に計算するので、Leanの結果がそのまま当てはまります）。
- NURBSのノット挿入は、挿入したパラメーターでの一致と凸結合性だけを証明しています。全パラメーターでの形状保存はテストで確かめています。
- `findSpan`と基底関数の評価、導関数はLeanでモデル化していません。
- 位相の一般的な性質は組合せ的な補題と箱への適用だけで、`validateBrep`の検査そのものは証明していません。
