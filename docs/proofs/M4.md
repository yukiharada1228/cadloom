# M4 の証明対応表

M4で`formal/CadloomFormal/`に追加したLeanの定理（`Interval.lean`、`IntersectCurve.lean`、`IntersectSurface.lean`、`Query.lean`）と、TypeScriptの実装・テストの対応表です。M0〜M3と同じく`node formal/scripts/verify.mjs`（`npm run prove`）で確かめます。このスクリプトは`lake build`を実行し、全定理の公理を監査して、`propext`・`Classical.choice`・`Quot.sound`の3つ以外に依存しないことを確かめます。Mathlibは使っていません。統合時点では20モジュール・538定理（M4で137定理を追加）が通っています。

## 読み方（共通の前提）

- 前提は[M0.md](M0.md)〜[M3.md](M3.md)と同じです。Leanのモデルは**厳密な数学**（`Nat`・`Bool`・`Int`・`Rat`・`List`・`Option`）で、TSの関数と同じ式・同じ順序・同じデータ構造で書いてあります。TSは倍精度浮動小数点で計算します。**IEEE-754の丸めそのものは証明していません。**区間演算の外向き丸めは「丸めた端点は真の値の外側にある」という抽象的な性質（`widen_mem`）として使い、その性質が実装で成り立つことは二進有理数による厳密な比較のテストで確かめます。
- M4の設計の原則（upstream `docs/ssi.md` §1、`docs/definitions-and-certificates.md`）: 交差の答えは必ず次の3つのどれかです。
  - **exact**: 閉じた式が成分の数と種類を決めた答え（直線/直線の有理数のCramerの公式、直線/平面、直線/二次曲面の判別式、平面/平面、平面/球の円、同軸の回転面など）。報告する倍精度の値は閉じた式を一度丸めたもので、`deviation`はその丸めの残差を測った値です。
  - **certified**: 証明で枝刈りした探索（交わらないことが**証明された**組だけを捨てる）で成分を見つけ、各点をNewton法で求め、入力からの最大偏差`deviation`を測った答え。接触は`contact: 'tangent'`、重なりは`overlap`として区別します。
  - **拒否**: 値ではなく`Result`のエラーで、`operation`が理由を名指しします（`refusalReason`: `tangent contact not resolved`、`subdivision budget exceeded`、`recursion depth exceeded`、`newton did not converge`、`degenerate input`、`precision exhausted`）。成分の数を黙って間違えることはありません。
- Leanが保証するのは主に(1) **除外の健全性**（区間・箱・平均値形式・Krawczyk作用素で「根がない」と判定した組には本当に根がない）、(2) **閉じた式の正しさ**（TSと同じ式の解が両方の入力の上にある）、(3) **探索の完全性**（作業リストのモデルで、接触を含む矩形は決して捨てられない）、(4) **問い合わせの判定規則**（半開の交差規則の偶奇、向きの反転への不変性、レイの出入り、箱による枝刈り）です。
- 実数・平方根・三角関数はcore Leanにありません。平方根は仮定`s * s = disc`を持つ有理数の変数、余弦・正弦の対は`c² + s² = 1`を持つ変数で表します。平均値の定理と区間の連鎖律`G'(T) ⊆ ∇G(box)·C'(T)`は仮定として与えます。
- 「テスト」列の名前は`tests/*.test.ts`の`test(...)`名（先頭部分）です。定理名と同じ名前（または定理名を含む名前）のテストが、実装に対して同じ性質を確かめます。
- 「補題」は他の定理の証明のための補助的な定理で、対応するTSの関数はありません。
- 仮定は満たすことができます（空虚な定理ではありません）。例: `Interval.lean`の具体例（区間と箱の値）、`plane_sphere_*`の仮定は具体的な球と平面で同時に満たされ、`boundary_meridian_frame`は`e = (1, 0, 0)`、`Z = (0, 0, 1)`で満たされます（レビュー時に確認）。

## 既知の限界（M4全体）

- Leanの定理は有理数の厳密なモデルについてのものです。IEEE-754の丸め、平均値の定理と区間の連鎖律（仮定）、Newton法の収束、標本に基づく判定は証明していません。
- **interval**: ノット挿入の丸め誤差の上界`γ_{16(L+2c+1)}·M`と有理商の広げ方は文書化した導出で（upstream `distance_bound.rs`と同じ見積もり）、Leanでは仮定です。区間の`sin`・`cos`・`acos`・`atan`は`Math`の関数が2 ulp以内であることを仮定します（`2^40`を超える引数は`[-1, 1]`）。解析形状の包含箱は区間評価なので依存性による広がりがあり、細分で狭まります。NURBSの法線錐は部分曲面のホドグラフの凸包なので、小さな部分になるまで緩やかです。
- **曲線の交差**: 重なり・接触・拒否の区別は接触の区間の17点の標本で決めます。許容誤差の帯の中で分離できない2根は1つの接触点として報告します（例: 直線の`1e-6`下に沈む放物線）。解析曲面は自然な全体（無限の平面・円柱・円錐）で扱い、面のトリムはしません。接触や近接の場合は1件あたり0.3〜1秒かかります。`1e12`の規模の曲線は細分の予算で拒否されます。
- **曲面/曲面**: 球の極を通る曲線は拒否します（極でパラメーターが退化）。境界の探索は相手の曲面の全体で行うため、相手のパッチの外の接触で不要な拒否が起きることがあります。完全性の「覆われている」判定、近接の受け入れ、重複の種の判定は測定に基づく発見的なもので、証明していません。フィットした曲線の偏差は区間の中点とデータ点で測ります（upstream `ssi.md` §6.1と同じ）。特異な分岐点（鞍点、等しい半径の8の字）は`tangent contact not resolved`として拒否します。平面/円錐の放物線・双曲線は閉じた式を持たず、追跡でcertifiedのNURBSを返すか拒否します。閉じた式の成分は解析曲面の全体で報告し、パラメーター範囲へのトリムは面の分類（M5の集合演算）の仕事です。
- **query**: 曲がったトリムは`(u, v)`の多角形です。辺の帯の中の点は`on`と報告し、そこを通るレイは捨てるので、粗い多角形が点の判定を決めることはありませんが、帯の外では証明されていません。`faceArea`は多角形の`(u, v)`領域で積分します。トリムした面の包含箱は`(u, v)`の箱の上の曲面全体です。最近点は`projectPoint`の足が唯一の局所最小であることを仮定します（トーラス・NURBSでは保証されず、足が一意でないときは33×33の標本による上界で`method: 'sampled'`）。楕円・NURBSの辺の距離は保守的です。`classifyPoint`は推測せず、24方向のレイで決まらなければ名指しの拒否です。曲面の軸の許容誤差以内の点も拒否します。
- **統合時に直した不具合**: 円錐の母線に沿って頂点を通る直線が、重なりではなく1点（exact、接触）として返っていました（母線の上では二次式の係数が丸め誤差の大きさになり、頂点の式が偽の点を作る）。円錐の曲面は1つのnappe（`R(v) ≥ 0`）なので、直線が頂点の平面を範囲の内側で横切るときは、nappeの側の部分が曲面上にあるかを先に調べ、あれば頂点から範囲の端までの1つの重なりとして報告するようにしました（`coneGeneratorPiece`、`src/intersect/curve-surface.ts`）。頂点で終わる範囲は頂点の1点、反対側だけの範囲は空です。テスト`line/cone: a line along a generator through the apex is one overlap …`。これで`rayBody`もそのようなレイで正しい重なりを受け取ります。
