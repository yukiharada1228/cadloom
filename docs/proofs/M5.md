# M5 の証明対応表

M5で`formal/CadloomFormal/`に追加したLeanの定理（`Heal.lean`、`Imprint.lean`、`Boolean.lean`）と、TypeScriptの実装・テストの対応表です。M0〜M4と同じく`node formal/scripts/verify.mjs`（`npm run prove`）で確かめます。このスクリプトは`lake build`を実行し、全定理の公理を監査して、`propext`・`Classical.choice`・`Quot.sound`の3つ以外に依存しないことを確かめます。Mathlibは使っていません。統合時点では23モジュール・628定理（M5で90定理を追加）が通っています。

## 読み方（共通の前提）

- 前提は[M0.md](M0.md)〜[M4.md](M4.md)と同じです。Leanのモデルは**厳密な数学**（`Nat`・`Bool`・`Int`・`Rat`・`List`）で、TSの関数・表と同じ定義・同じ順序で書いてあります。TSは倍精度浮動小数点と許容誤差で計算します。**幾何（交線、点の分類、標本、メッシュの体積）は証明していません。**
- M5の設計の原則（upstream `docs/booleans.md` §8、`docs/validity-and-tolerances.md`）: 集合演算の答えは必ず次のどれかです。
  - **solid**: `validateBrep`と`validateBrepGeometry`を通り、recordで往復し、水密で正の体積のメッシュになる閉じた立体（塊ごとに1つの`body`、空洞は内側の殻）。
  - **empty**: 選ばれた断片がないとき（`A ∩ B = ∅`、`A − A`、`A ⊆ B`での`A − B`）。kernelに有効な空の`Brep`はないので、空は物体ではなく結果の種類です。
  - **拒否**: 値ではなく`Result`のエラーで、理由を名指しします（交差の`tangent contact not resolved`、刻印の`non-manifold imprint`、分類の`inconsistent classification`、組み立ての`non-manifold result`・`orientation mismatch`・`assembly failed`・`invalid result`、縫合の`not-closed`・`non-manifold`・`shells-intersect`など）。不正な物体や黙って間違えた物体を返すことはありません。
- 処理の流れ（upstream `booleans/pipeline.svg`と同じ段階）は、(1) 面/面の交差と刻印（`faceFaceIntersection`、`imprintBodies`。M4の`intersectSurfaces`・`intersectCurveSurface`・`pointInFace`だけを使う）、(2) 断片の分類（`classifyFragments`。M4の`classifyPoint`だけを使う）、(3) 選択表（`SELECTION`）、(4) heal による組み立て（`sewFacesReport`、`mergeCosurfaceFaces`、`removeRedundantVertices`）と最終の検証です。
- Leanが保証するのは主に(1) **組み合わせの判断**（union-findのラベル、BFSによる向きの伝播の完全性と拒否の健全性、刻印の各段階のEuler–Poincaréの保存、パラメーター区間の分割）、(2) **選択表の正しさ**（表が残す断片は正則化した結果の境界にちょうど1回、外向きの向きで一致すること）と集合演算の代数法則、(3) **TSの結果の物体の個数**（テストの物体と同じ`V`・`E`・`F`・`L`と種数）です。
- 「テスト」列の名前は`tests/*.test.ts`の`test(...)`名（先頭部分）です。定理名と同じ名前（または定理名を含む名前）のテストが、実装に対して同じ性質を確かめます。
- 「補題」は他の定理の証明のための補助的な定理で、対応するTSの関数はありません。
- 仮定は満たすことができます（空虚な定理ではありません）。例: `splitIntervals_*`の`Increasing`は`0 < 1 < 2`で満たされ、`propagate_complete_forest`は`forest_example`（2つの成分）で、`runMerges_*`は`runMerges_example`で具体的に満たされます。`emit_eq_expected`は16通りの全ての所属のパターンと3つの演算について`decide`で確かめます（レビュー時に`on-same`・`on-opposite`のパターンを手でも確認）。

## 既知の限界（M5全体）

- Leanの定理は組み合わせと選択表についてのものです。交線、点の分類、標本、縫合の距離、メッシュの体積は証明していません（実行時の検証で守ります）。
- **接触と特異点**: 接する接触（面に触れる球、等しい半径の直交する円柱のSteinmetz、`1e-6`の隙間）は`tangent contact not resolved`で拒否します。辺や点だけで接する2つの塊の和は`non-manifold result`で拒否します（解決はしない）。半径の違う同心の球で極の軸が違うものは`non-manifold imprint`で拒否します。球の両極の約`0.013`以内を通る平面は、一様な標本の3次のpcurveのフィットが極での`(u, v)`の跳びを追えず`precision exhausted`で拒否します。
- **刻印**: 円弧を残すか捨てるかは円弧の中点の`pointInFace`で決め、まっすぐな`(u, v)`のトリムでは正確ですが、それ以外では辺の帯の中の多角形です。フィットしたpcurveの偏差は測った値（`zone/4`以内）で、証明していません。同じ面で別の刻印の曲線の内部で終わる刻印、接する成分、両方の面の上にある孤立した交点、面を分けずに2つのループをつなぐ刻印は拒否します。2つの面の組が同じ曲線を作るとき、`EdgeSource.piece`には最初の部分のidだけが残ります。下位の段階の拒否が、集合演算の名前ではなく下位のエラー（`closestPointOnCurve`の`not-converged`、極の近くの`precision exhausted`）のまま届くことがあります。
- **分類**: レイによる点の分類なので証明はありません。内部の標本のクリアランスは3Dではなく尺度を合わせた`(u, v)`で測り、20×20の格子より薄い断片は領域のラベルを使います。直接分類するのは領域ごとに2つの断片までで、残りは領域のラベルを写します（レビューで全ての断片を分類しても全てのラベルが一致し、速さも変わらないことを確かめました）。統合後の結果の面の由来（provenance）は、併合を通して追うのではなく、残した断片の標本点を結果の面の上で探して決めます。
- **縫合（heal）**: 各殻の外向きは表示メッシュの体積の符号で決めます（体積が`zoneTol3d·diag²`以内の殻や、メッシュにできない殻は`zero-volume`で拒否）。頂点の束は「許容誤差以内」の推移閉包なので鎖は許容誤差より広くなりえます（隙間の報告に出て、幾何の検証が拒否）。辺の一致は内部の5点の標本と最近点で、NURBSでは大域最小を保証しません。交差が報告しない`zoneTol3d`より小さな隙間は接触として扱いません（`0.5`ゾーン離れた2つの球は2つの有効な塊になる）。`mergeCosurfaceFaces`は同じパラメーター付けの曲面の面だけを併合し、継ぎ目を失う周期的な面は併合しません。`removeRedundantVertices`は同一直線の線分と、同じ円の連続した円弧だけをつなぎます（`O(V·(E+C))`）。
- **他の層の既知の問題（レビューで見つけ、M5では直していないもの）**: `validateBrepGeometry`は重なって置かれた2本の別の辺を受け入れます（角で接する2つのポケットの物体が検証を通り、水密にメッシュにならない例）。面に`0.03`未満だけ食い込む円柱の刻印は有効な物体になりますが、既定の表示の許容誤差では小さな蓋の断片が2頂点のループになり水密にメッシュになりません（弦`1e-6`では水密。`tess`の問題）。曲がったトリムの面のメッシュの体積は既定の設定では収束が遅いので（例: 円柱 − スロットで0.8%小さい）、曲面の体積の検査は`angleDeg: 2`、`maxEdgeLength: 0.1`で行います。
- **入力**: `Brep`の型を満たさない値（`null`、`{faces: []}`）を渡すと、M4の`prepared`・`prepareBody`の中で`TypeError`を投げます（M2から後送りしている「信頼できない`Brep`値の検証」）。
- **速さ**: 集合演算1件は数十ms〜約2秒（Steinmetzの追跡した交線）で、例の時間の多くは細かい表示メッシュです。
