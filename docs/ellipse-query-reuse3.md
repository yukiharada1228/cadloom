# 不変な楕円の厳密照会の再利用

共通Booleanで「辺接触する二つの箱と、その一方の内部に収まる円柱との積」を計測しました。CPUプロファイルでは、楕円弧上の点判定、角度比較、そのための正確な有理数・多項式演算が目立ちました。支持楕円のスナップショットを毎回作り直すことで、既存の平面フレームの再利用も失っていました。

`ellipse3` で構築した楕円は、フレーム・原点・方向・正の半径二乗を検査して不変な値を持ちます。内部スナップショットでその同一性を維持し、次をWeakMapで再利用します。

- 支持平面と、一般の非直交共役軸に対する双対ベクトル。
- 不変な点の楕円内外判定。
- 不変な点の角度半周分類と、二点間の角度比較。

計算式や交差候補、完全な境界照合は変更しません。初回の計算結果だけを、検査済みの楕円とスナップショットされた点の同一性で保存します。同じ数値に見える別の構造体を幾何的に同一視して省略する変更ではありません。

外部の構造コピーは、ルートが凍結されていても所有された楕円とは扱いません。毎回、フレームと半径を再スナップショット・検査します。外部の点も、現在の座標から不変なスナップショットを作ります。コピーのフレーム・半径・座標が変わった後に、古い判定を返してはいけません。キャッシュはWeakMap／WeakSetで持ち、到達不能な楕円や点をグローバルな強参照で保持しません。ただし生存している入力への照会結果の分だけメモリを使い、使用量の固定上限は保証しません。

## 検証

独立した局所二次不等式で非直交フレームの点分類を照合し、位相の独立した並びで角度順・継ぎ目越え・逆向き弧を検査します。外部の凍結ルートに残る可変フレーム、半径・点座標の変更、無効化された軸と弧端点を、照会を繰り返した後でも拒否・再分類できることを確認します。

SSI点、独立した代数的端点、楕円交差、共通材料Booleanの既存回帰も確認します。これらは実行テストであり、TypeScript全体の形式証明ではありません。

## 再現するベンチマーク

```sh
npm run build
node benchmarks/material-contact-cylinder.ts
```

固定の合成形状を使い、接触材料の作成・曲面との積・保存・再構築を個別に計測します。再構築後の内部・境界・外部を検査し、全保存結果のSHA-256、面・辺数、文字数とメモリ観測値を出力します。時間やメモリは閾値テストにはしません。

比較時はNode・機械・バックグラウンド負荷を揃え、入力と全保存結果が同じであることを確認してください。並行して動く全体回帰によって時間は変動します。一例の短縮を、任意のCADモデルの実用性能や一定の高速化率の保証とは扱いません。


## 今回の観測

同じ合成入力を変更前・最終変更後の別プロセスで順に一回ずつ実行しました。CPUプロファイルを付けない比較での観測値です。

| 処理 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 共通Booleanの積 | 19451 ms | 11606 ms |
| 保存文書からの再構築 | 28842 ms | 11491 ms |

全保存結果をバイト単位で照合して一致しました。双方とも8面・14辺・33221文字、SHA-256は `79066100cdd5090a247057490106c1cd8cd8877c575d856e206a028faff80c0f` です。バックグラウンドで旧版の全体回帰が動いているため、この一回の差から一定の高速化率は主張しません。

最終レビュー対象の隔離ビルドで、新規3件を含む関連29件が成功（31696 ms、失敗・スキップ0）。楕円の交差・位相・SSI・代数的端点・平面フレームの既存回帰に加え、共通材料Booleanと旧Body入口を含みます。最終テストとベンチマークの型検査、ソースハッシュ照合、既存133宣言の限定監査も成功しました。新しい機械証明やTypeScript全体の形式検証ではありません。

同梱ベンチマークをレビュー対象の隔離ビルドに対して実行した際は、積14301 ms・再構築14026 msで、同じ保存結果ハッシュでした。Node v26.12.0 / darwin / arm64。この再実行でも時間は変動しており、単発の速度比を性能保証には使いません。
