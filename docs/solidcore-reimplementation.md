# SolidCraft / SolidCoreのピュアTypeScript再実装方針

cadloomは、SolidCraftの構成と操作を参照し、ピュアTypeScriptでCADを実現する。最初にSolidCore相当のカーネルを進め、その後スケッチ・履歴・コマンド・アプリケーションへ広げる。現在の厳密幾何実装を再利用する。全機能の移植やAPI互換が既に成立したという意味ではない。

## 参照を固定する

今回の調査対象はSolidCraftのコミット[`cd20a1fe14062cc1642e1c04fb9805f86d9e2eef`](https://github.com/tangency-labs/solidcraft/tree/cd20a1fe14062cc1642e1c04fb9805f86d9e2eef)。追随先を勝手にmainへ動かさず、参照更新は差分をレビューする。

- [全体構成](https://github.com/tangency-labs/solidcraft/blob/cd20a1fe14062cc1642e1c04fb9805f86d9e2eef/docs/architecture.md)：geom → sketch/kernel → doc → io → engine → front ends。
- [SolidCore](https://github.com/tangency-labs/solidcraft/blob/cd20a1fe14062cc1642e1c04fb9805f86d9e2eef/solidcore/README.md)：`solidcore/`が開発元。別リポジトリはミラー。SMLibを基にしたB-repカーネルであり、統合途中の経路もある。
- [カーネル内の層](https://github.com/tangency-labs/solidcraft/blob/cd20a1fe14062cc1642e1c04fb9805f86d9e2eef/solidcore/docs/layers.md)：record、kernel、convert、ops、tess、appsを分ける。
- [定義と保証](https://github.com/tangency-labs/solidcraft/blob/cd20a1fe14062cc1642e1c04fb9805f86d9e2eef/solidcore/docs/definitions-and-certificates.md)：幾何の定義、近似表現、誤差保証を区別する。

[対応表](solidcore-coverage.json)は、24の責務について参照パス、現在のローカルソース、不足部分を記録する。`partial`は関連実装があるという意味で、移植済み・API互換・テスト互換を表さない。ローカル基準は`bc5a004c3cc9eb66429ee609e76e5b2516b65b47`。作業ブランチの機能と公開npmの機能を混同しない。

## 層と責務

| 層 | cadloomでの責務 | 最初に揃えるもの |
|---|---|---|
| record | 保存・交換できるデータと構造検査 | バージョン、幾何表、頂点・辺・ループ・面・シェル・領域、参照ID、向き |
| kernel | 幾何計算と幾何的成立条件 | 数値、曲線・曲面、交差、位置分類、位相更新 |
| convert | recordとカーネル所有オブジェクトの変換 | 正確な数値の復元、構造検査と幾何検査の区別 |
| ops | カーネルを呼ぶ操作手順 | primitive、extrude、split、booleanの一貫したBody入出力 |
| tess / io | 表示・入出力 | 境界を共有するメッシュ、STEP変換、近似の誤差情報 |
| sketch / doc / engine / app | 制約・履歴・セッション・UI | カーネル操作を利用する。幾何演算の別実装を持たない |

レコードは関数・WeakSet・実行時キャッシュを含まない。構造上正しいレコードと、幾何的に認定した立体は別の型・処理にする。配列の要素数や閉じた接続表だけでは、面の埋め込みや立体の成立を認定しない。操作結果は次の操作へ渡せる共通Body表現を持つ。入力がtriangle solidかextrusionかclipped cylinderかによって、公開操作が別の世界に分かれた状態を解消する。

## 数値とピュアTypeScriptの条件

- 実行時の幾何計算はTypeScriptから生成したJavaScriptのみ。Rust/WASM、ネイティブアドオン、外部CADサービスへ計算を委譲しない。
- 有理数・代数的数と、現在の厳密な述語・構成を再利用する。Rustの浮動小数処理を置き換えただけで数学的厳密性が得られるとは考えない。
- 形状の定義と表示用の近似を分ける。メッシュでモデルの接続や交差の正否を決めない。
- 非有理・非代数的な結果には適切な表現が必要。例えば円柱の体積にはπが現れる。有理数やAlgebraicRealに無理に押し込まず、記号式または根拠を持つ上下界を設計する。
- 厳密値、保証付き近似、未対応・未認定を区別する。未認定を「交差なし」「有効な面」に読み替えない。許容誤差を広げて失敗を成功に変えない。
- 近似を導入する各操作は、何を囲む上下界か、単位、要求精度、停止・拒否条件を明記する。現時点で汎用の保証付き超越関数演算が実装されたとは主張しない。

## 開発順と完了条件

### M1：共通Bodyと基本プリミティブ

Box、有限Cylinder、既存の直線・円弧プロファイルのExtrudeを同じレコード・同じ操作入口で扱う。参照先は`solidcore-record`、`solidcore-convert`、`primitive::api_primitives::{create_box,create_cylinder}`、`solidcore-ops`。最初から全てのRust型名やメモリ構造を互換対象にはしない。

完了条件：

1. 頂点・共有辺・辺の使用方向・面の支持面と領域・シェル・材料領域が共通Bodyに結びつく。解析曲面を三角形へ置き換えない。空の結果、複数の材料成分、貫通穴と閉じた空洞の違いを表現できる設計にする。
2. Box・Cylinder・Extrudeを作成し、同じ方法で境界・厳密な内外判定・構造診断へアクセスできる。
3. 正確な数値をJSONの浮動小数へ丸めず保存・復元する。バージョン、不正ID、欠落した参照、向きの矛盾、無効な幾何をそれぞれ検出する。構造検査だけで任意入力へ幾何認定を付与しない。
4. boxの解析式、円柱の独立した不等式、直線プリズムと既存三角形立体との照合で結果を検証する。非単位の軸・移動・向き・極小寸法も扱う。入力の受理条件を文書化する。
5. 公開入口だけを使う実行例と回帰テストがある。単に既存オブジェクトを包んだだけで共通Body化が完了したとはしない。

### M2：交差・分割・接続・ブーリアン

曲面交差のパラメータ対応、面領域への制限、共有境界の分割、面片の分類、接続の再構築を共通Body上でつなぐ。既存の平面／円柱分割やsewingを再利用し、一般の解析面・NURBSへ広げる。

完了条件：和・差・積が同じBody型を返す。接触、完全一致、部分重複、空集合、複数成分、穴、内部空洞で正則化の意味を固定する。穴付きプレートや交差する立体で、境界の成立・独立した点分類・量の整合性を確認する。2Dプロファイルの差を押し出した例を、汎用3Dブーリアンの実装完了とは数えない。

### M3：解析プリミティブ・生成操作・計測

Sphere、Cone、Torus、Revolve、Sweep、Loft、距離・最近点・レイ照会、体積・面積・重心・慣性を拡張する。手順に必要なカーネル機能をその都度実装する。操作ごとに成立条件と数値結果の種類を固定し、独立した解析式または別実装で照合する。

### M4：Blend・Offset・Healing

Fillet、Chamfer、Shell、厚み付け、輸入形状の修復。手続き的曲面の定義と近似・保証を保持する。半径が大きすぎる場合、接触の退化、自己交差、特異点を明示的に扱う。形状をこっそり変更する修復を通常の厳密演算に混ぜない。

### M5：メッシュとSTEP

共有辺に沿った整合する分割、面内部の三角形分割、誤差条件を満たす表示メッシュ、STEPの解析とレコード変換を実装する。STEP往復で位相・支持形状・トリム・単位を確認する。STEP対応を商用CADの全ネイティブ形式対応とは呼ばない。

### M6：SolidCraft相当の上位層

スケッチ制約、パラメータ式、フィーチャ履歴、増分再生成、共通コマンド、CLI/MCP、ブラウザUIへ進む。保存・Undo/Redo・再生成で同じ操作結果を保つ。Assemblies、板金等の製品ワークフローも上位層の追加対象として残す。カーネルが未完成という理由で永遠にアプリを先延ばしにはせず、必要な操作が通った単位で接続する。

## 移植の検証単位

各操作の変更は、参照コミットと関数、対応するローカル入口、受理入力、出力、不足経路、独立した照合結果を記録する。上流goldenは差分検出用であり、正しさそのものの証明とはしない。期待値を生成した実装と同じ実装だけで正否を決めない。

RustやFreeCAD等を開発時の比較に使うことは、製品の実行時依存とは区別する。採用するケースは出典・単位・精度・再現手順を持つ。未実装経路にstubの成功値を返して件数を稼がない。性能も、呼び出し数だけでなく、部品の演算時間・ピークメモリ・BigIntや代数的数の増大を記録する。

形式証明は重要な数学へ絞り、実装には独立オラクル・退化例・入力変換に対する不変条件を使う。既存Lean定理数やソースハッシュは、再実装全体の形式証明を意味しない。

## 出典・ライセンスの扱い

SolidCraftのコードはMIT OR Apache-2.0、SolidCoreはApache-2.0で、SolidCoreのNOTICEはSMLib/SM_API由来を明記している。実コードを翻訳・移植するときは該当する出典・ライセンス・NOTICE・変更内容を残す。現時点のこの計画では外部実装コードを取り込んでいない。

SolidCraftの名称・ロゴ・UI素材等は別条件のため、cadloomのUIやブランドをそのまま複製する計画には含めない。数値仕様や未実装経路も含めて参照し、上流が完全・無欠陥だという前提を置かない。
